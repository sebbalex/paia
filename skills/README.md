# gws skills — vendored reference

**Not the assistant's skills.** Those live in `.claude/skills/`, are written
in this repo, and are switched on by name in `ASSISTANT_SKILLS` — see "Skills"
in `ROT.md`. This folder is a copy of somebody else's documentation that
happens to use the same file format.

Google's own agent skills for the `gws` CLI (`@googleworkspace/cli`), kept
here as a local copy so the command surface is versioned with this repo
instead of being fetched when it happens to be needed.

Generated by `gws generate-skills` from the installed CLI, **version 0.22.5**,
on 2026-08-19. Pruned to the three services that are authenticated:
calendar, gmail, drive — plus `gws-shared`, which the others list as a
prerequisite. Every `../gws-*/SKILL.md` cross-link inside the kept files
resolves; nothing points at a skill that was dropped.

## What these are for, and what they are not

**They are reference, not a capability.** A skill tells an agent to run
`gws calendar events list …` in a shell. The assistant has no shell: `Bash` is
absent from `Config.tools`, listed in `disallowed_tools`, and default-denied
in `assistant/policy.py`. Nothing here changes that, and nothing here should
be read as permission to try.

The assistant reaches Google through `assistant/gws.py` instead: three
in-process tools that run the same CLI with an argv list built in Python, with
the method table fixed and read-only. When that grows to Gmail or Drive, these
files are where the exact resources, methods and parameters come from —
`gws-gmail/SKILL.md` for the API surface, `gws-gmail-read/SKILL.md` for how
Google expects a read to be composed.

Skills whose subject is a write (`gws-gmail-send`, `gws-calendar-insert`,
`gws-drive-upload`) are kept because they document the shape of the API, not
because the assistant may perform them. Sending, creating and deleting stay
with the owner, per rule 5 in `ROT.md`.

## Using them yourself

They are not in `.claude/skills/`, and the assistant is given an explicit list
of skill names (`ASSISTANT_SKILLS`), so nothing here is ever loaded into it.
To make them live in your *own* Claude Code sessions:

```bash
ln -s ../../skills/gws-calendar .claude/skills/gws-calendar
```

Do that per skill you actually want. Leaving them unlinked is the default on
purpose: the assistant's session loads project settings too, and a skill it
cannot execute is noise at best.

## Regenerating

```bash
gws generate-skills     # writes ./skills for ALL 95 skills, relative to cwd
```

It takes no useful flags — `--help` runs it. Run it from a scratch directory
and copy across what you want, or expect to prune the other 81 again.
